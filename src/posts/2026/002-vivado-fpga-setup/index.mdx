# Terminology

I want to start off by documenting the terminology and how they fit together. Otherwise it's all a bit overwhelming.

## Constraints

Your FPGA will necessarily include some IO ports, otherwise it cant do anything useful.
The chip itself does not know or care about what each port does - it might be a USB peripheral,
it might be an LED, it might be a digital audio jack, it might be a clock signal. This decision needs
to be made on a port by port basis.

For an integrated FPGA, these assignments will have already been made by the manufacturer, but a production deployment
might have you developing your own boards with these chips. Because of this, there's a lot of flexibility and control in
how you assign these ports. To handle this, your project needs to define some "constraints" which guides the "place and route"
system.

For my Z7-20, all it took was to download the [constraint file provided by Digilent](https://github.com/Digilent/Arty-Z7-HW/blob/20/master/src/constraints/Arty-Z7-20-Master.xdc)

To explain how the constraints format works, let's take a look at an example:

```tcl
set_property -dict { PACKAGE_PIN H16    IOSTANDARD LVCMOS33 } [get_ports { clk }]; #IO_L13P_T2_MRCC_35 Sch=SYSCLK
create_clock -add -name sys_clk_pin -period 8.00 -waveform {0 4} [get_ports { clk }];#set

set_property -dict { PACKAGE_PIN M20    IOSTANDARD LVCMOS33 } [get_ports { sw[0] }]; #IO_L7N_T1_AD2N_35 Sch=SW0
set_property -dict { PACKAGE_PIN M19    IOSTANDARD LVCMOS33 } [get_ports { sw[1] }]; #IO_L7P_T1_AD2P_35 Sch=SW1
```

There's quite a lot to break down here.

First, the `.xdc` file format is actually just [Tcl](https://en.wikipedia.org/wiki/Tcl_(programming_language)).
Tcl is common amongst Vivado tooling.

Next, let's look at `PACKAGE_PIN H16`. This defines the physical port on the FPGA. The `H16`, `M19`, and `M20` are grid
coordinates that define the location on my FPGA's Ball Grid Array (BGA). Some simple FPGAs might only have a few pins,
so they can get away with a linear naming scheme, but a more complex component will use BGA to mount to the board.

`IOSTANDARD LVCMOS33` defines the IO standard for the port, obviously. 
This is [LVCMOS](https://en.wikipedia.org/wiki/LVCMOS) (Low voltage complementary metal oxide semiconductor) at 3.3 volts.
I don't know how this information is used during routing. I'm not going to play around with this, I'd rather not break it :D

`get_ports { sw[0] }` is a Tcl procedure provided by Vivado that finds the logical port named `sw[0]`. The `sw` input
will be defined as having 2 bits, and we can address each bit individually.
